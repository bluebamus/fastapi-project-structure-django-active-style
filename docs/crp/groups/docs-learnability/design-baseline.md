# Design Baseline — Docs Learnability (기준 설계 문서)

> 이 그룹의 요구사항·설계 결정의 단일 기준. append-only.

## 0. 질의 수준 (Autonomy Level)

- [x] **보통(Balanced)** — 핵심 갈림길만 질문, 자명한 건 기본값 + 한 줄 고지.

선택: **보통** · 선택일: 2026-08-20

## 1. 목적 / 배경

이 저장소는 **참조 구조(reference structure)** 다. 즉 산출물이 동작하는 코드만이 아니라
**개발자가 규칙을 배워 가는 것**까지가 목적이다. 사용자의 표현으로는 이렇다:

> "이 프로젝트 구조를 사용하는 개발자들이, django 스타일의 app 을 자동으로 인지하는 구조,
> 그리고 raw 쿼리를 사용하는 경우, orm 을 사용하는 경우에 대해 각 워크플로우 및 개발 룰을
> 이해하고 학습할 수 있기를 원한다."

2026-08-20 검수 결과 두 목표 중 **하나만** 달성돼 있었다.

- **앱 자동 인지: 달성.** README 전용 섹션 + 생성기 + 8개 실동작 앱 + 자동배선 테스트로
  학습 경로가 완결돼 있었다.
- **ORM/Raw 워크플로: 미달성.** 자료가 없어서가 아니라 **도달할 수 없어서**였다.
  1,206행 지침서와 두 완결 예제(catalog/reports)가 있는데 README·QUICKSTART·ARCHITECTURE
  어디에도 언급이 **0건**이었고, 링크도 없었다.

핵심 문제는 하나로 요약된다: **학습 자료는 깨져도 아무도 실패하지 않는다.** 코드는
테스트가 지키지만 문서는 끊겨도 초록이고, 그 사실은 새로 온 사람이 헤맬 때에야 드러난다.

## 3. 설계 결정 기록 (ADR)

| ADR-ID | 날짜 | 결정 | 근거 | 상태 |
|---|---|---|---|---|
| ADR-001 | 2026-08-20 | 원본 지침서(`docs/specs/orm-raw-repository/workflow-guide.md`)를 **옮기지 않고**, 학습용 가이드 `docs/guides/orm-raw-workflow.md` 를 **새로 쓴다**. | 최초 계획은 "승격(이동)" 이었으나, 코드(`app/core/db/router.py`, `session.py`)와 테스트 3종이 그 지침서를 `workflow-guide §7` 형태로 인용하고 있었고, CRP 이력 문서들도 그 경로를 기록으로 참조한다. 이력은 **당시의 사실**이라 고쳐 쓰면 안 된다. 사본을 만들면 두 문서가 갈라진다. 그래서 원본은 *설계 기준선*으로 두고, 학습 가이드는 **코드를 가리키는 짧은 문서**로 새로 쓴다 — 코드는 테스트가 지키므로 드리프트가 구조적으로 억제된다. | **Superseded (→ ADR-005)** — "옮기지 않는다" 부분만. 학습 가이드를 따로 둔다는 결정은 유지 |
| ADR-002 | 2026-08-20 | 학습 경로를 **테스트로 강제**한다(`tests/test_docs_learnability.py`). | 문서는 깨져도 실패하지 않는다는 것이 이 그룹의 근본 문제다. 링크·예제 실재·예제가 여전히 그 Base 를 쓰는지를 검사하면, 학습 경로가 조용히 끊기는 일을 막을 수 있다. 문장 품질은 검사하지 않는다 — 검사 가능한 것만 검사한다. | Accepted |
| ADR-004 | 2026-08-25 | **현행을 참칭하는 문서는 갱신이 아니라 삭제한다.** 날짜 고정 문서라도 "현행 배선"·"현재 코드 상태" 를 주장하면서 실제로 틀렸다면 갱신 블록으로 덧대지 않고 지운다. | 갱신 블록은 원문이 **당시의 기록임을 스스로 밝히는** 문서에서만 작동한다(ADR-003·F-204 선례). `concepts/auto-discovery-registry`(현행 배선이라 소개된 `create_app()` 시대 도식)와 `01-project-hardening-plan`("기준선 교체 후 재확인한 실제 적용 여부" 라 적힌 상태표의 3/4 가 이후 해소돼 거짓이 됨)은 둘 다 독자에게 현재를 주장한다. 이런 문서에 갱신 블록을 붙이면 "틀린 본문 + 정정" 이 공존해 읽는 비용만 늘고, 정정 링크가 끊기면 틀린 본문만 남는다(F-207 이 관측한 고장 모드). | Accepted |
| ADR-003 | 2026-08-20 | 날짜가 붙은 문서 폴더는 **"설계 기준선"** 으로 명시하고, 살아 있는 문서와 역할을 구분해 `docs/README.md` 에 표로 고정한다. | 학습자가 `docs/` 의 5개 하위 폴더 중 무엇부터 볼지 알 수 없었다. 날짜 폴더를 "지난 기록" 으로 읽고 건너뛰는 판단은 틀리지 않았다 — 실제로 그 안의 둘은 과거 기록이다. 문제는 **셋 중 하나만 지금도 유효한 지침서**라는 사실이 어디에도 없었다는 점이다. | Accepted |
| ADR-005 | 2026-09-17 | 착수 명세 3종을 날짜 폴더에서 `docs/specs/orm-raw-repository/` 로 **옮기고**, 그 경로를 가리키던 CRP 문서·버전 가이드의 참조를 새 경로로 바꾼다(경로만, 내용 불변). `review_gate` docs 그룹은 `docs/guides/`·`docs/README.md` 도 검사한다(변경 이력 절 제외, HTML 은 `<code>` 경로 포함). | `.gitignore` 가 `YYYY-MM-DD/` 폴더를 로컬 작업 기록으로 빼면서 명세가 저장소에서 사라졌고, CRP 문서가 가리키는 경로가 없어 docs 게이트가 CI 에서 실패했다. ADR-001 이 우려한 "이력 소급 수정" 은 경로 문자열 교체로 한정한다 — 파일이 실재하지 않는 경로를 두면 기록을 따라갈 수 없다. 코드 주석의 `workflow-guide §N` 인용은 새 위치에서도 그대로 성립한다. | Accepted |
| ADR-006 | 2026-09-17 | **한 주제 = 한 문서.** 문서 목록은 README 「문서 안내」 절 하나에만 두고(`docs/README.md` 삭제), 같은 내용의 MD/HTML 병행을 없애며, 날짜·버전이 박힌 현행 문서를 두지 않는다. 앱 자동화 명세(개념 02 + 명세 03)는 코드·테스트 주석이 인용하는 요구사항 ID(`FR/CR/NFR/BC/SEC/AC`)와 설계 근거만 남겨 `docs/specs/django-style-app-automation.md` 한 파일로 합친다(타 저장소 이관 계획은 폐기). 개발 가이드는 파일명 `orm-raw-workflow.md` 를 유지한다. 학습 경로 검사는 새 소유 문서로 옮기고, 버전 가이드 갱신 블록 링크 검사는 README·docs 전체(crp 제외) 상대 링크 검사로 넓힌다. CRP 이력이 가리키는 삭제 경로(`docs/README.md`·QUICKSTART)는 기록을 고치지 않고 게이트 후방 참조 면제로 둔다. | 같은 사실이 README·QUICKSTART·ARCHITECTURE·HTML 2종·project-guide 에 반복되며 서로 어긋나 있었다(없는 Repository 메서드, "앱이 운영 차단을 하지 않는다" ↔ `validate_deployment_safety()`, 라우트 18/30 ↔ 22/37, 로그 포맷·파일 핸들러 조건, 옛 세션 별칭). 사본이 많을수록 갱신 누락이 생긴다(ADR-004 의 고장 모드). 개발 가이드 파일명을 바꾸면 `scripts/new_app.py` 출력 문자열(동작 코드, C-1)과 CRP 이력 경로를 함께 바꿔야 한다. | Accepted |
