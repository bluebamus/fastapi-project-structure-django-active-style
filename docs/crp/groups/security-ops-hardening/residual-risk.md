# Residual Risk — security-ops-hardening (잔여 위험 등록부)

> **재기 금지 목록.** 여기 "수용(Accepted)"으로 박제된 항목은 *의도적으로 고치지 않기로* 결정된
> 것이다. 다음 라운드에서 이걸 새 finding 으로 다시 올리면 안 된다. 고쳐야 하면 그것은
> "새 결함"이 아니라 **계약 변경 제안** — charter 를 먼저 바꾼다.

| ID | 항목 | Severity | 왜 비범위인가(계약 근거) | 수용일 | 재평가 조건 |
|---|---|---|---|---|---|
| R-601 | **해소(2026-10-19, admin-session-hardening F-002)** — `/admin` 의 모든 POST·PUT·PATCH·DELETE 를 `AdminCsrfMiddleware` 가 세션 토큰으로 검사하고 로그아웃은 POST 전용이 됐다(ADR-004). 원 기록: 로그인 이후 sqladmin 이 그리는 생성·수정·삭제 폼과 GET `/admin/logout` 에는 CSRF 토큰이 없다 — `SameSite=Strict`·`Path=/admin` 이 1차 방어다. | LOW | 명세 §3 범위 밖. sqladmin 0.32 의 폼은 sqladmin 이 그리고 토큰 훅이 없다. 주요 브라우저는 모두 Strict 를 지원한다(admin-login R-302 의 남은 부분). | 2026-10-19 | 같은 사이트의 다른 하위 도메인이 신뢰할 수 없는 콘텐츠를 서비스하게 되거나 Strict 미지원 클라이언트를 지원해야 하면, `/admin` 하위 앱에 상태 변경 메서드 전체를 보는 CSRF 미들웨어를 붙인다. |
| R-602 | **해소(2026-10-19, admin-session-hardening F-001)** — 사용자 결정(방법 2)으로 Redis 서버 세션으로 옮겼다. 로그아웃·강등·비활성화·삭제가 서버에서 즉시 폐기한다(ADR-001~ADR-003). 원 기록: 관리 세션은 서명 쿠키라 서버측 폐기 목록이 없다(admin-login R-301 그대로). Redis 로 옮기는 안은 **사용자 결정 대기**. | LOW | 사용자 결정 대기(명세). | 2026-10-19 | 사용자가 Redis 세션 이전을 결정하면 새 요청으로 charter 를 연다. |
| R-603 | 보존 삭제는 Celery **beat** 가 떠 있어야 돈다. beat 를 안 띄우면 지워지지 않고 경고도 없다. beat 를 둘 띄우면 하루 두 번 발행된다(삭제는 멱등이라 결과는 같다). | LOW | ADR-002. 실행 토폴로지는 배포의 몫이다 — README 운영 확인 8·명령으로 안내한다. | 2026-10-19 | 운영에서 beat 미기동이 관측되면 `/ready` 나 기동 로그에 "마지막 정리 시각" 점검을 검토한다. |
| R-604 | `hide_parameters` 는 SQLAlchemy 가 만드는 문자열만 덮는다 — 드라이버가 자체 메시지에 값을 싣거나(예: 일부 `DataError` 의 원문), 앱 코드가 값을 직접 로그에 쓰면 막지 못한다. 진단에 바인드 값이 필요할 때는 재현 환경에서 옵션을 잠시 끄는 것 외에 길이 없다. | LOW | ADR-001. 값 자체를 알아볼 수 없어 로그 마스킹으로는 한계가 있다(log-redaction-fixes R-402). | 2026-10-19 | 드라이버 원문에 값이 실리는 사례가 관측되면 그 예외 타입의 메시지를 번역기(`DBErrorTranslator`)처럼 타입명만 남기도록 감싼다. |
| R-605 | 보존 삭제는 "id 선택 → DELETE" 두 구문이라 그 사이에 다른 프로세스가 같은 행을 지우면 반환 수가 실제보다 클 수 있다(같은 정리 태스크가 동시에 돌 때만). | LOW | ADR-002. beat 하나 전제이고, 결과(지워짐)는 같다. | 2026-10-19 | 정리 태스크를 병렬로 돌릴 필요가 생기면 `CursorResult.rowcount` 로 센다. |
| R-606 | **해소(2026-10-19, admin-session-hardening F-003)** — 기간 연산(`range`)과 전용 필터 템플릿이 생겨 빠른 선택(오늘·최근 7일·30일)을 기간 링크로 둔다(ADR-005). 원 기록: 날짜 필터의 빠른 선택(오늘·최근 7일·30일)은 없다. | LOW | ADR-004. sqladmin 연산 필터 화면은 값 입력이 필수라 한 필터에 담을 수 없다. "최근 7일" 은 `이후(포함)` 에 날짜를 넣는다. | 2026-10-19 | 운영자가 빠른 선택을 요구하면 같은 클래스에 lookup 필터를 하나 더 두거나 템플릿을 덮어쓴다. |
