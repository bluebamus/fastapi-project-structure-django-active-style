PROJECT GUIDE

API 인증 흐름

JWT 발급·회전·폐기와 그 한계입니다.

허브 부팅 설계 API 설정 요청 인증 기능 개발 테스트 운영

도식은 고정 버전 Mermaid CDN을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

인증 모델

API 는 Bearer JWT 를 씁니다. access token(기본 15분)은 DB·Redis 조회 없이 서명·만료·타입과 클레임(sub·username·su)만 검증합니다. refresh token(기본 7일)은 jti·family 를 Redis 의 RefreshTokenStore 에 기록해 회전·폐기합니다. 관리 화면(/admin)의 쿠키 세션은 별도 경계입니다.

한계와 보안 의도

  • access token 은 만료(ACCESS_TOKEN_EXPIRE_MINUTES, 기본 15분) 전에 폐기할 수 없습니다. 로그아웃·재사용 감지·권한 변경은 refresh 만 끊습니다.
  • /me 외의 보호 경로는 토큰 클레임만 봅니다. 비활성화·슈퍼유저 강등은 기존 access token 이 만료될 때까지 그 경로에 반영되지 않습니다(이때 refresh·관리 세션은 즉시 폐기).
  • rate limit 은 가입(IP 5회/3600초)과 로그인 두 경로만입니다. refresh·logout 은 제한하지 않습니다.
  • 모든 401 은 WWW-Authenticate: Bearer 를 싣습니다. Redis 장애 시 가입·로그인·refresh·logout 과, refresh·관리 세션 폐기가 따르는 사용자 변경(비활성화·강등·비밀번호 변경·삭제)은 503 입니다(성공으로 간주하지 않음). Redis 를 쓰지 않는 요청은 그대로 응답합니다.
  • 라우트 접근 수준과 리소스 소유권은 분리돼 있습니다. 작성자·본인 규칙은 서비스가 판정합니다.
