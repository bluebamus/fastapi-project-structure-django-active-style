요청 처리 흐름

미들웨어 순서, 세션·트랜잭션, 오류 변환, 접속 로그입니다.

허브 부팅 설계 API 설정 요청 인증 기능 개발 테스트 운영

도식은 고정 버전 Mermaid CDN을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

설계 목적

HTTP 경계의 관측·오류 변환과 기능 유스케이스를 분리합니다. 미들웨어는 모든 요청에 필요한 일만 하고, 접근 수준·세션·서비스는 의존성이, 업무 규칙은 서비스가, commit 은 쓰기 View 가 맡습니다.

처리 순서

미들웨어는 CORS → UserInfo → answer_unhandled_exception 순서로 등록되고 Starlette 는 나중 것을 바깥에 두므로, 요청은 answer_unhandled_exception → UserInfoMiddleware → CORS → 라우터 순서로 들어갑니다.

세션과 트랜잭션

  • 기능 라우터는 조회에 get_read_only_db_session(쓰기 시도는 ReadOnlyRoutingError), 쓰기에 get_writer_db_session(primary 고정)을 씁니다.
  • get_routed_db_session(구문을 보고 엔진 선택)은 승인된 특수 경로 전용입니다. 지금 기능 코드는 쓰지 않으며 tests/core/test_session_dependency_names.py 가 강제합니다.
  • 트랜잭션 경계는 쓰기 View입니다. 쓰기 핸들러가 응답 DTO 를 먼저 검증한 뒤 await service.commit() 을 한 번 호출합니다. 서비스는 업무 규칙만, 저장소는 flush 까지만 하고 둘 다 commit 하지 않습니다. 세션은 의존성(get_writer_db_session·get_read_only_db_session)이 열고, 예외로 빠져나가면 세션 close 가 ROLLBACK 합니다. 순서는 tests/test_dto_before_commit.py 가 고정합니다.

처리기를 거치지 못하고 올라온 예외는 가장 바깥의 answer_unhandled_exception 이 같은 Exception 처리기로 500 을 돌려줍니다(traceback 한 번, keep-alive 유지). DEBUG=true 면 이 미들웨어는 예외를 다시 던집니다.

접속 로그

ACCESS_LOG_ENABLED=true 면 UserInfoMiddleware 가 응답 뒤 저장 작업을 제출하고, home 앱의 apps.ready() 가 등록한 sink 가 background 세션으로 저장합니다. 저장 실패는 응답을 바꾸지 않고, 남은 작업은 종료 시 lifespan 이 정리합니다. 제외 경로·확장자와 query string 마스킹은 환경 설정을 봅니다.
