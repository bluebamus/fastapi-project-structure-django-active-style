PROJECT GUIDE

부팅과 첫 실행

환경 준비부터 설정 검사, lifespan 기동·종료까지의 첫 실행 절차입니다.

허브 부팅 설계 API 설정 요청 인증 기능 개발 테스트 운영

도식은 고정 버전 Mermaid CDN을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

목적

개발 환경을 재현하고 서버를 처음 띄우는 절차입니다. 설정 검사는 lifespan 이 아니라 config.py import 시점에 실행되므로, 잘못된 설정은 서버가 요청을 받기 전에 RuntimeError 로 드러납니다. 자세한 명령과 표는 README 빠른 시작이 정본입니다.

필수 절차

  1. uv sync 로 잠금 파일 기준 의존성을 설치합니다.
  2. cp .env.example .env 후 ACCESS_TOKEN_SECRET_KEY·REFRESH_TOKEN_SECRET_KEY·SESSION_SECRET_KEY 를 서로 다른 32자 이상 값으로, MYSQL_PASSWORD 를 실제 비밀번호로 바꿉니다. 예시 값·빈 값·짧은 키·access=refresh 이면 개발 환경에서도 기동하지 않습니다. 키 생성: uv run python -c "import secrets; print(secrets.token_urlsafe(48))". Redis 설정은 로컬 기본값(localhost:6379)이면 바꿀 필요가 없습니다.
  3. Redis 7.0 이상을 띄웁니다. Redis 는 필수입니다 — 기동 시 PING 이 실패하거나 버전이 7.0 미만이면 시작하지 않습니다(DEBUG=false 로도 우회되지 않습니다).
  4. MySQL 을 준비합니다. DEBUG=true(기본값)면 기동 때 create_all 로 테이블을 만들므로 MySQL 이 없으면 startup 이 실패합니다. Alembic 으로 관리할 때는 uv run alembic upgrade head 를 먼저 적용합니다.
  5. uv run python main.py(SERVER_HOST·SERVER_PORT, DEBUG 면 reload) 또는 uv run uvicorn main:app --reload --port 8000 로 실행합니다.
  6. 첫 슈퍼유저를 만듭니다: uv run python -m scripts.create_superuser --username admin --email admin@example.com. 관리 API 와 /admin 은 슈퍼유저 전용이고 API 로는 첫 슈퍼유저를 만들 수 없습니다.
  7. GET /health(DB 를 보지 않음)와 GET /ready(writer DB SELECT 1·Redis PING, 각 2초)를 구분해 확인합니다. /docs·/openapi.json 은 DEBUG=true 일 때만 열립니다.

실패를 읽는 법

  • 설정 위반은 config import 에서 한 번에 모아 보고합니다. 메시지에 고칠 설정 이름만 나오고 값은 나오지 않습니다.
  • Redis 는 필수입니다. 기동 중 PING 실패·7.0 미만이면 시작하지 않고, 실행 중 Redis 연결이 끊기면 Redis 를 쓰는 요청(가입·로그인·refresh·logout, 사용자 수정·삭제의 세션 폐기, /admin)은 503, /ready 도 503 입니다. Redis 를 쓰지 않는 조회 API 는 계속 응답합니다.
  • DEBUG=false 에 MySQL 이 없으면 기동은 되지만 /ready 는 503, 기능 API 는 500 입니다.
  • /ready 는 SELECT 1 과 PING 만 봅니다. 마이그레이션과 모델이 어긋난 것은 잡지 못하고 요청 시점에 실패하므로 배포 전에 alembic upgrade head 를 적용합니다.
  • 종료 시 lifespan 이 등록 역순으로 자원을 정리합니다. 단계별 예산과 순서는 서버 수명주기 안내서에 있습니다.
