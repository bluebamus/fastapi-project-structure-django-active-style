9. 오류 응답과 health / ready

글로벌 핸들러 4종이 모든 오류를 ErrorResponse{error_code, message, detail} 로 바꿉니다.

예외 응답
AppException 계열 (NotFoundException, DuplicateException, ValidationException, DatabaseException, 기능 예외) 예외가 정한 상태 코드·error_code·detail
RequestValidationError 422, detail 에 field·message·type 목록. OpenAPI 도 모든 operation 의 422 를 이 형식(ErrorResponse)으로 광고한다 — FastAPI 기본 HTTPValidationError 는 main.py 의 문서 후처리가 바꾼다
Starlette HTTPException 해당 상태, error_code=HTTP_<status>. 예외의 headers 를 그대로 싣는다(405 Allow·401 WWW-Authenticate 등)
그 밖의 Exception 500 INTERNAL_SERVER_ERROR, 고정 메시지, detail=null — DEBUG 여부와 무관

500 의 예외 타입·route template·스택은 로그에만 남습니다(경로에 박힌 식별자 대신 template). Repository 의 DB 오류 변환(DBErrorTranslator — MySQL 오류 코드·SQLite 메시지로 중복 409·필수 값 422·참조 없음 422·참조 중 409·그 외 500)도 드라이버 원문을 응답에 싣지 않습니다. AppException 은 상태 코드 500 이상만 ERROR(detail 포함)로, 4xx 는 WARNING 으로 남기고 4xx 의 detail(클라이언트가 보낸 값)은 로그에 싣지 않습니다. 경로는 route template 입니다. 회귀 가드: tests/test_exception_handler_leak.py, tests/core/test_db_error_translator.py.

경로 / 지점 의미 결과
GET /health 프로세스 생존·버전 (DB·Redis 검사 없음) {"status":"healthy","version":...}
GET /ready writer 로 SELECT 1 과 Redis PING 을 동시에, 각 2초 guard 둘 다 성공 status="ready", 하나라도 실패 503 NOT_READY (예외 메시지·DSN 없음, 로그는 대상과 예외 타입만)
/docs, /openapi.json DEBUG=true 일 때만 아니면 404
설정·registry 오류 lifespan 이전 조립 실패 프로세스 기동 실패
Redis ping·개발 DDL 실패 startup 실패 등록된 자원 정리 후 중단
커밋 실패 쓰기 핸들러 안에서 예외 성공 응답 전에 오류 응답
접속 로그 포화·저장 실패 응답과 분리 로그 경고, dropped 증가

/health 만으로 DB·Redis 준비를 판단하지 않습니다. 오케스트레이터의 readiness 는 /ready 에 겁니다 — DB 와 Redis 를 모두 봅니다.
