12. Alembic

migrations/env.py 는 런타임과 같은 발견 규칙으로 모델을 모읍니다. 새 앱을 추가해도 이 파일은 고치지 않습니다. FastAPI lifespan 에 들어가지 않으므로 Redis ping 도 하지 않습니다.

_registry = AppRegistry()
_registry.discover()
_registry.import_models()
target_metadata = Base.metadata
config.set_main_option(
    "sqlalchemy.url",
    db_settings.ALEMBIC_URL.render_as_string(hide_password=False).replace("%", "%%"),
)
  • URL 우선순위(DatabaseSettings.ALEMBIC_URL, URL 객체): ALEMBIC_DATABASE_URL 설정값(make_url) → primary URL 의 드라이버만 mysql+pymysql 로 바꾼 값. env.py 는 환경변수를 직접 읽지 않습니다.
  • DSN 은 문자열로 이어 붙이지 않고 URL.create(...) 로 만듭니다 — 비밀번호의 @ / : # 는 렌더링 때 인코딩되고, % 는 ConfigParser 보간을 피하려고 %% 로 넘깁니다. 회귀 가드: tests/core/test_dsn_urls.py.
  • revision 체인: f4adf0ae24ea(baseline) → b2f1a9c0d3e4(user 비밀번호) → c3d5e7a91b02(catalog_products) → d4e6f8b12c34(sales_orders) → e5a7c9d1f3b5(시각 컬럼 UTC·DATETIME(6)) → a7c3e9f1b2d4(슈퍼유저·작성자 id 컬럼, head).
  • e5a7c9d1f3b5 는 MySQL 에서만 동작합니다(SQLite no-op). 기존 값을 CONVERT_TZ(col, '+09:00', '+00:00') 로 옮기므로 기존 데이터가 +09:00(Asia/Seoul 벽시계)으로 저장됐다는 가정입니다 — 적용 전에 백업하고, 다른 시간대로 운영하던 DB 는 적용 전에 리비전의 _LOCAL_OFFSET 상수를 그 오프셋으로 바꿔야 합니다(README 운영 배포 확인 7). downgrade 는 역변환 후 DATETIME 으로 좁힙니다(소수 초 반올림).
  • autogenerate 는 UTCDateTime 을 sa.DateTime().with_variant(mysql.DATETIME(fsp=6), "mysql") 로 적습니다 (env.py 의 render_item=render_alembic_type) — 리비전이 앱 클래스를 import 하지 않습니다.
  • 서버 기동은 upgrade 를 하지 않습니다. 운영은 트래픽 전환 전에 alembic upgrade head 를 적용합니다.
  • 회귀 가드: tests/core/test_migration_chain.py(빈 DB upgrade head 결과 = ORM metadata), tests/core/test_alembic_metadata.py, 게이트 structure 그룹(alembic heads 단일 head).

작성 절차는 기능 개발 가이드 §10, 자동 생성과의 전환은 README 를 봅니다.
