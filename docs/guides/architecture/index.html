PROJECT GUIDE

아키텍처

앱 자동 등록 규약과 View·Service·Repository 책임 분리입니다.

허브 부팅 설계 API 설정 요청 인증 기능 개발 테스트 운영

도식은 고정 버전 Mermaid CDN을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

앱 자동 등록

app/core/registry.py 의 AppRegistry 가 app/features 의 직계 하위 패키지를 이름 알파벳순으로 발견합니다(_ 로 시작하는 이름 제외). 중앙 등록 목록은 없고, 규약 파일이 있으면 붙습니다. 상세는 ARCHITECTURE §2가 소유합니다.

오류 정책은 "파일 부재는 선택, 잘못된 계약은 오류"입니다. 선택 모듈이 없으면 건너뛰고, 모듈 안의 import 오류는 그대로 올리고, 모듈은 있는데 export 가 틀리면 AppContractError 로 기동을 멈춥니다. 조립이 끝나면 AccessPolicyGuard().verify(app) 가 모든 API 뷰의 접근 수준 선언을 검사해, 없거나 모순이면 같은 AppContractError 로 기동을 거부합니다.

조립 순서

  1. registry.discover() — 앱 목록 확정(부수효과 없음)
  2. registry.install_hooks() — 각 앱의 apps.ready()(예: home 의 접속 로그 sink 등록)
  3. registry.import_models() — 모델을 Base.metadata 에 등록
  4. FastAPI 생성 → 미들웨어(CORS, UserInfo, answer_unhandled_exception) → 전역 예외 처리기
  5. registry.install_routers(app) → /health·/ready(DEBUG 면 /docs)
  6. ADMIN_DISABLED=false 면 /admin 마운트
  7. AccessPolicyGuard().verify(app)

RepositorySQL·ORM, flush, DB 예외 변환commit

트랜잭션 경계는 쓰기 View입니다. 쓰기 핸들러가 응답 DTO 를 먼저 검증한 뒤 await service.commit() 을 한 번 호출합니다. 서비스는 업무 규칙만, 저장소는 flush 까지만 하고 둘 다 commit 하지 않습니다. 세션은 의존성(get_writer_db_session·get_read_only_db_session)이 열고, 예외로 빠져나가면 세션 close 가 ROLLBACK 합니다. 순서는 tests/test_dto_before_commit.py 가 고정합니다.

기능은 core·utils·config 만 쓰고 다른 기능을 import 하지 않습니다. 예외는 auth → user(자격증명을 User 모델이 소유) 하나입니다.
