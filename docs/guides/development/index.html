새 기능 추가

  1. uv run python -m scripts.new_app <name> [--with-admin] 로 뼈대를 만듭니다. 이름은 파이썬 식별자여야 하고 이미 있는 앱은 덮어쓰지 않습니다(--force 로만).
  2. 규약 파일을 채웁니다: api/routers/router.py 의 <name>_router, models/, (선택) admin.py 의 admin_views, apps.py 의 ready(), tasks.py. main.py·migrations/env.py·app/features/admin.py 는 열지 않습니다.
  3. 모든 뷰에 접근 수준(Public·PublicWrite·LoginRequired·SuperuserRequired)을 하나 선언합니다. 빠지면 AccessPolicyGuard 가 기동을 거부합니다.
  4. 조회는 get_read_only_db_session, 쓰기는 get_writer_db_session 을 쓰고, 쓰기 View 는 응답 DTO 검증 뒤 await service.commit() 을 한 번 호출합니다.
  5. 모델이 바뀌면 uv run alembic revision --autogenerate -m "..." 로 revision 을 만들고 검토한 뒤 upgrade·downgrade 를 확인합니다.
  6. 새 API 는 tests/e2e/test_api_matrix.py 의 OPS 에 한 줄(정상·422·소유권·404) 더합니다. 빠지면 tests/e2e/test_inventory.py 대조가 실패합니다. tags_metadata 와 tests/test_route_inventory.py 도 갱신합니다.
  7. 재시작하면 라우터가 /api 에, 모델이 Base.metadata 에, admin_views 가 관리 화면에 붙습니다. API 표도 갱신합니다(문서 계약 테스트가 대조).

코드 리뷰 기준

  • 업무 규칙이 View 나 저장소로 새지 않았는가
  • commit 이 쓰기 View 한 곳(응답 DTO 검증 뒤)에만 있고 서비스·저장소에는 없는가
  • 조회 경로가 read-only 세션을, 쓰기 경로가 writer 세션을 쓰는가
  • 인증 실패(401)·권한 실패(403)·없음(404)·충돌이 공통 오류 계약을 따르는가
  • 비동기 함수 안에 블로킹 I/O 가 없는가
  • 새 API·설정이 문서화됐는가
