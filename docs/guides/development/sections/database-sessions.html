개발·확장의 세부 주제입니다. 목적·책임·운영 및 확장 시 지켜야 할 계약을 설명합니다.

7. 세션 선택과 주입

# app/features/catalog/dependencies/catalog_dependencies.py
async def get_catalog_service(
    session: AsyncSession = Depends(get_writer_db_session),
) -> CatalogService:
    return CatalogService(session)


async def get_catalog_service_readonly(
    session: AsyncSession = Depends(get_read_only_db_session),
) -> CatalogService:
    return CatalogService(session)
유스케이스 Dependency 규칙
조회 (복제 지연 허용) get_read_only_db_session 쓰기를 시도하면 ReadOnlyRoutingError. commit 없음. 라우터가 켜져 있으면 replica
쓰기, 조회 후 쓰기, 잠금 get_writer_db_session 첫 쿼리부터 writer. 응답 전 commit 1회
복제 지연을 허용할 수 없는 조회 get_writer_db_session writer 고정 조회, commit 없음
  • GET/POST 라는 이름이 아니라 유스케이스로 고릅니다.
  • 기능의 세션 Dependency 는 이 둘뿐입니다. 쓰기는 전부 get_writer_db_session, 조회는 전부 get_read_only_db_session 입니다. 동적 라우팅은 기능 코드에서 쓰지 않습니다 (tests/core/test_session_dependency_names.py 가 강제합니다).
  • 조회에 쓰기 세션을 재사용하지 않습니다. writer 가 자동 commit 하지는 않지만 read-only 보호와 replica 선택을 잃습니다. Raw 라는 이유로 쓰기 세션을 쓰지 않습니다 — Raw 는 접근 방식이지 권한이 아닙니다.
  • 여러 Service 가 한 원자적 쓰기에 참여하면 같은 writer 세션을 주입하고 commit 주체는 하나로 둡니다. 한 요청 안에서 같은 Dependency 는 재사용되지만 writer·read-only getter 는 서로 다른 세션입니다.
  • 인증 Dependency(get_current_user)가 read-only 세션으로 읽은 객체를 쓰기 세션에서 수정하지 말고, 쓰기 세션으로 다시 조회합니다.

세션 종류·라우팅 규칙 전체는 ARCHITECTURE §8에 있습니다.

7.1 라우트 보호 — 인증 · 슈퍼유저 · 소유권

권한은 슈퍼유저/일반 2단계입니다(ARCHITECTURE §10.2). 부품은 전부 core app.core.security(access·dependencies)에 있고, 기능은 이것만 import 합니다(다른 기능을 import 하지 않는다).

모든 뷰는 접근 수준 하나를 선언합니다. 경로 데코레이터의 dependencies=[...] 에 넣습니다. 선언이 없거나 모순인 뷰(둘 이상, 쓰기에 Public, 조회에 PublicWrite)가 하나라도 있으면 앱 조립 직후 AccessPolicyGuard 가 위반 목록 전체를 담은 AppContractError 로 서버 기동을 멈춥니다(기본 거부).

원하는 것 쓰는 것 실패
누구나 조회 (GET·HEAD·OPTIONS) dependencies=[Public] —
인증 없는 쓰기 (가입·로그인처럼 의도적으로 열 때만) dependencies=[PublicWrite] — 쓰기에 Public 을 쓰면 기동 거부 —
로그인한 누구나 핸들러 인자 principal: CurrentPrincipal(주체를 쓸 때) 또는 dependencies=[LoginRequired] 토큰 없음·만료·위조 401
슈퍼유저만 (주체를 쓰지 않음) dependencies=[SuperuserRequired]. 라우터 전체 APIRouter(dependencies=[...]) 도 판정에 인정되지만 예시는 뷰 단위로 적는다 401 / 403
슈퍼유저만 (주체를 씀) 핸들러 인자 admin: SuperuserPrincipal 401 / 403
작성자 본인 또는 슈퍼유저 서비스 생성자에 OwnershipPolicy(provider get_ownership_policy), 메서드가 principal 을 받아 self.policy.ensure_can_modify(entity.author_id, principal) 403 
from app.core.security.access import Public, SuperuserRequired
from app.core.security.dependencies import FORBIDDEN_RESPONSES, CurrentPrincipal

@router.get("/notes", dependencies=[Public], ...)                      # 공개 조회
async def list_notes(...) -> NoteListResponse: ...

@router.delete("/notes/{note_id}", dependencies=[SuperuserRequired], ...)  # 주체를 쓰지 않는 관리 경로
async def purge_note(...) -> None: ...

@router.patch("/notes/{note_id}", responses={**_NOT_FOUND, **FORBIDDEN_RESPONSES}, ...)
async def update_note(
    payload: NoteUpdate,
    principal: CurrentPrincipal,                      # 기본값 없는 인자 — 기본값 있는 인자보다 앞
    note_id: str = Path(...),
    service: NoteService = Depends(get_note_service),  # provider 가 OwnershipPolicy 를 주입
) -> NoteResponse:
    note = await service.update_note(note_id, payload, principal)  # 404 → 소유권 403
    ...

principal: CurrentPrincipal 인자가 곧 LoginRequired 선언이라 같은 수준을 데코레이터에 다시 적지 않습니다 (SuperuserPrincipal 은 SuperuserRequired). 소유자 판정은 선언이 아니라 서비스가 하므로 수정·삭제 뷰의 선언은 LoginRequired 입니다.

왜 @login_required 처럼 함수를 감싸지 않는가. FastAPI 는 뷰 함수의 시그니처를 읽어 의존성 주입·요청 검증·OpenAPI 를 만듭니다. 함수를 감싸는 데코레이터는 그 시그니처를 가리거나(functools.wraps 로 겉모습을 복사해도 주입할 인자와 실제 호출 인자가 어긋난다) OpenAPI 의 security 표시를 잃게 만듭니다. 그래서 접근 수준은 FastAPI 가 원래 제공하는 경로 데코레이터의 dependencies=[...] 에 선언하고, 데코레이터가 못 하는 "선언을 잊은 뷰 막기" 는 기동 시 검사(AccessPolicyGuard)가 맡습니다.

  • 인증 주체는 토큰에서 만들고 DB 를 조회하지 않습니다. 사용자 엔티티가 꼭 필요할 때만 auth 의 get_current_user 를 씁니다(/me).
  • 작성자 컬럼은 요청 본문에서 받지 않습니다 — 서비스가 principal.id·principal.username 으로 채우고, Update 스키마에 넣지 않습니다.
  • 존재 여부 자체가 비밀이면(예: 사용자) 존재 확인 전에 판정해 404/403 차이로 떠볼 수 없게 합니다.
  • 새 operation 은 뷰에 접근 수준을 선언하고(없으면 기동 거부) README 권한 표에 더합니다. 예시 기능의 operation 이면 tests/test_authorization.py 의 EXPECTED 표에도 더합니다 — 가드의 판정과 OpenAPI security 표시(로그인 필요 여부)를 함께 대조합니다.
  • 테스트는 인증 의존성을 override 하지 말고 tests/auth_headers.py(user_headers()· other_user_headers()·superuser_headers())로 실제 서명된 토큰을 보냅니다.
