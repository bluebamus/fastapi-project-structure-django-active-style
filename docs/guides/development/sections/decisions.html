1. 먼저 정할 것

개발·확장의 세부 주제입니다. 목적·책임·운영 및 확장 시 지켜야 할 계약을 설명합니다.

1. 먼저 정할 것

  1. 새 앱이 필요한가. 기존 기능에 엔드포인트 하나를 더하면 되는 일이면 그 기능 안에서 합니다.
  2. HTTP 계약 — method·경로·입력·공개할 응답 필드·오류 응답.
  3. 데이터 소유 — 새 테이블인가, 기존 테이블의 계산 결과인가(§4 의 선택 기준).
  4. 읽기/쓰기 의도 — 조회만인가, 조회 후 쓰기인가, 잠금이 필요한가(§7).
  5. 권한 — 공개·로그인·작성자 본인(또는 슈퍼유저)·슈퍼유저 전용 중 무엇인지 정합니다(§7.1, ARCHITECTURE §10.2). 인증 성공과 수정 권한은 별개입니다. 정한 수준은 뷰마다 선언합니다 — 선언하지 않은 뷰가 하나라도 있으면 서버가 기동하지 않습니다.
  6. 동시성·멱등성 — 재고 차감·상태 전환은 "조회 후 UPDATE" 만으로 안전하지 않습니다. 조건부 UPDATE·잠금·DB 제약 중 무엇을 쓸지 정합니다.
