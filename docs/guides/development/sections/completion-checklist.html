12. 완료 체크리스트

  • [ ] uv run python -m scripts.new_app <name> (또는 규약대로 수동 생성)
  • [ ] models/models.py + models/__init__.py 재노출, Alembic revision 생성·검토 (env.py 는 그대로)
  • [ ] schemas/ — 입력/출력 분리, description, 공개 필드 확정
  • [ ] repositories/ — ORM 이면 BaseRepository, Raw 면 RawRepositoryBase (+ query_name, named bind)
  • [ ] services/ — 업무 규칙, Raw 결과는 여기서 DTO 로
  • [ ] dependencies/ — 쓰기용·조회용 getter 둘 다
  • [ ] api/routers/v1/ — operation_id, DTO 검증 → commit 1회 / router.py 의 <name>_router
  • [ ] 권한 — 뷰마다 접근 수준(Public·PublicWrite·LoginRequired·SuperuserRequired, §7.1)을 선언 (선언하지 않은 뷰가 있으면 서버가 기동하지 않는다), 소유권은 서비스의 OwnershipPolicy, README 권한 표· tests/test_authorization.py 의 EXPECTED 갱신
  • [ ] 필요하면 admin.py 의 admin_views (민감 필드 제외 확인 — /admin 은 슈퍼유저 로그인·Redis 세션· CSRF 미들웨어 뒤에 있고 ADMIN_DISABLED=true 면 import 되지 않으므로 뷰에 인증·CSRF 를 따로 넣지 않는다. created_at 이 있으면 column_filters 에 LocalDateFilter(Model.created_at)(같은 날·이후·이전·기간). 상태를 바꾸는 작업을 sqladmin @action(GET)으로 만들지 않는다 — CSRF 검사 대상이 아니다), apps.py 의 ready()
  • [ ] 태그 설명(app/core/tags_metadata.py), tests/test_route_inventory.py, README API 표 갱신
  • [ ] 새 operation 은 tests/e2e/test_api_matrix.py 의 OPS 에 한 줄(정상·422·소유권·404 요청) — 없으면 -m e2e 의 인벤토리 대조가 실패한다
  • [ ] 테스트 작성, mysql 마커 대상 SQL 확인, 게이트 실행
  • [ ] Celery 태스크가 필요하면 기능 폴더의 tasks.py 에 추가 (중앙 파일 수정 없음)
