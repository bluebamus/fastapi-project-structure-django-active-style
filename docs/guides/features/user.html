사용자 기능

사용자 관리와 본인·슈퍼유저 접근 규칙, 비활성화·강등·비밀번호 변경·삭제 시 세션 폐기를 담당합니다.

허브 부팅 설계 API 설정 요청 인증 기능 개발 테스트 운영

도식은 고정 버전 Mermaid CDN을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

목적과 책임

사용자 관리와 본인·슈퍼유저 접근 규칙, 비활성화·강등·비밀번호 변경·삭제 시 세션 폐기를 담당합니다.

핵심 패턴: 본인 또는 슈퍼유저 정책 + 비활성화·강등·비밀번호 변경·삭제 시 refresh·관리 세션 폐기

  • 본인 수정에서 is_active·is_superuser 를 보내면 403(PrivilegedFieldException)입니다. 슈퍼유저만 바꿀 수 있습니다.
  • 비활성화(is_active 참→거짓)·강등(is_superuser 참→거짓)·비밀번호 변경이나 사용자 삭제면 그 사용자의 refresh family 와 관리 세션을 폐기합니다. 활성화·승격 등 그 밖의 수정은 유지합니다(revocation_for). 이미 발급된 access token 은 만료(기본 15분)까지 남습니다.
  • 첫 슈퍼유저는 API 가 아니라 scripts/create_superuser.py 로 만듭니다.
  • 트랜잭션 경계는 쓰기 View입니다. 쓰기 핸들러가 응답 DTO 를 먼저 검증한 뒤 await service.commit() 을 한 번 호출합니다. 서비스는 업무 규칙만, 저장소는 flush 까지만 하고 둘 다 commit 하지 않습니다. 세션은 의존성(get_writer_db_session·get_read_only_db_session)이 열고, 예외로 빠져나가면 세션 close 가 ROLLBACK 합니다. 순서는 tests/test_dto_before_commit.py 가 고정합니다.

사용과 확장

클라이언트는 API 레퍼런스의 접근 수준을 만족한 뒤 OpenAPI 스키마에 맞춰 호출합니다. 프로필과 자격 증명 변경을 분리하고 민감 필드는 응답 스키마에서 제외합니다.

  1. 요구사항과 접근 수준·소유권 규칙을 먼저 정합니다.
  2. 스키마 → 저장소 → 서비스 규칙 → View 순서로 책임을 배치합니다.
  3. migration 과 테스트를 같은 변경에 포함하고, 새 API 는 tests/e2e/test_api_matrix.py 의 OPS 에 한 줄 더합니다.
  4. API 가 바뀌면 이 문서와 전체 API 표를 함께 갱신합니다.

주의점

  • commit 은 쓰기 View 에서 응답 DTO 검증 뒤 한 번입니다. 서비스·저장소에서 commit 하지 않고, View 에서 쿼리를 조립하지 않습니다.
  • 목록 API 는 정렬·페이지 경계를 안정적으로 유지합니다.
  • 없음(404)과 권한 실패(403)를 구분하되 내부 정보를 노출하지 않습니다.
