  • 트랜잭션 경계는 쓰기 View입니다. 쓰기 핸들러가 응답 DTO 를 먼저 검증한 뒤 await service.commit() 을 한 번 호출합니다. 서비스는 업무 규칙만, 저장소는 flush 까지만 하고 둘 다 commit 하지 않습니다. 세션은 의존성(get_writer_db_session·get_read_only_db_session)이 열고, 예외로 빠져나가면 세션 close 가 ROLLBACK 합니다. 순서는 tests/test_dto_before_commit.py 가 고정합니다.

사용과 확장

클라이언트는 API 레퍼런스의 접근 수준을 만족한 뒤 OpenAPI 스키마에 맞춰 호출합니다. 재고·가격 이력은 상품 테이블에 누적하지 말고 별도 도메인으로 분리합니다.

  1. 요구사항과 접근 수준·소유권 규칙을 먼저 정합니다.
  2. 스키마 → 저장소 → 서비스 규칙 → View 순서로 책임을 배치합니다.
  3. migration 과 테스트를 같은 변경에 포함하고, 새 API 는 tests/e2e/test_api_matrix.py 의 OPS 에 한 줄 더합니다.
  4. API 가 바뀌면 이 문서와 전체 API 표를 함께 갱신합니다.

주의점

  • commit 은 쓰기 View 에서 응답 DTO 검증 뒤 한 번입니다. 서비스·저장소에서 commit 하지 않고, View 에서 쿼리를 조립하지 않습니다.
  • 목록 API 는 정렬·페이지 경계를 안정적으로 유지합니다.
  • 없음(404)과 권한 실패(403)를 구분하되 내부 정보를 노출하지 않습니다.
