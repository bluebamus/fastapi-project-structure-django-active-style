PROJECT GUIDE

환경 설정

config.py 의 Settings 전체와 설정 검사 규칙입니다.

허브 부팅 설계 API 설정 요청 인증 기능 개발 테스트 운영

도식은 고정 버전 Mermaid CDN을 사용합니다. 인터넷이 없어도 본문·표·도식 원문을 읽을 수 있습니다.

사용 원칙

설정의 정본은 config.py 의 Settings 클래스이고, 설명이 붙은 예시는 .env.example 입니다. 우선순위는 프로세스 환경 변수 → 작업 디렉터리의 .env → Field 기본값입니다. .env.example 은 자동으로 읽히지 않습니다. 운영 비밀은 저장소에 커밋하지 않고 환경 변수로 주입합니다.

설정 검사 — config import 시점

ENV=test 는 검사하지 않습니다(pytest 가 지정). 위반은 한 번에 모아 RuntimeError 로 보고하며 메시지에는 설정 이름만 담습니다.

검사범위거부 조건
.env 출처test 외 모든 ENV.env 가 없는데 환경 변수에 ENV·비밀 키 3종·MYSQL_HOST/USER/PASSWORD/DATABASE(8개) 중 하나라도 없음
비밀 키test 외 모든 ENVACCESS_TOKEN_SECRET_KEY·REFRESH_TOKEN_SECRET_KEY·SESSION_SECRET_KEY 가 placeholder(change-this 포함, your- 시작, 빈 값)이거나 32자 미만, access=refresh
DB·Redis 비밀번호test 외 모든 ENVMYSQL_PASSWORD 가 placeholder 또는 빈 값, REDIS_PASSWORD 는 값이 있을 때만 placeholder 검사
배포 조합staging·productionDEBUG=true, CORS_ALLOW_ORIGINS 에 *, LOG_SQL_ECHO_ENABLED=true, LOG_LEVEL=DEBUG
옛 이름test 외 모든 ENV.env·환경 변수에 ADMIN 이 남아 있음(ADMIN_DISABLED 로 바뀌었고 의미가 반대)

형식 오류(JSON 배열, bool, 로그 형식 필드, 음수 보존 일수, 모순된 DB 라우터 조합 등)는 각 Settings 의 validator 가 같은 import 시점에 거부합니다.

확장 방법

  1. 해당 Settings 클래스에 타입·안전한 기본값·description 을 가진 필드를 추가합니다.
  2. .env.example 에 비밀이 아닌 예시와 설명을 추가합니다(config.py 와의 일치를 테스트가 강제합니다).
  3. 새 비밀 설정(*_USER·*_PASSWORD·*SECRET*·*_KEY)은 config.LOG_SECRET_SETTINGS 에 등록합니다. 빠지면 tests/utils/test_logging_overhaul.py 가 실패하고, 등록된 값은 로그에서 가려집니다.
  4. 서로 의존하는 값은 validator 나 설정 검사에서 기동 시 실패시킵니다.
  5. 이 표에 행을 더합니다(누락은 문서 계약 테스트가 잡습니다).
